## How it works

`index/` is built **offline from the unmodified pinned sqlglot commit
`eb11aec4be8cb2122afe713a4816662c3f0fb2fa` only** (`tools/trace_suite.sh`). The
build runs the pinned suite once under coverage.py with a tracing plugin
(`tools/rwx_trace.py`) and records, per test:

- line coverage, with import-time execution (`import|module`) and test-module
  collection kept in separate contexts, and class/module fixtures (`setUpClass`)
  credited to every test of the class;
- the files each test opened (fixtures, and source files read as data);
- every sqlglot class each test instantiated (with MRO), incl. dialect lookups,
  and the modules whose *import* instantiated it (e.g. SQL templates parsed in
  a class body);
- every module each test requested via `import` (cached or not).

The suite's `ProcessPoolExecutor` work is run in-process (with a pickle round
trip) during tracing so optimizer/executor fixture tests are actually measured.
No sample patch, answer or edit kind is used to build anything.

At runtime, for each patch:

1. Parse the unified diff; apply it to the packaged pinned source.
2. Compare old/new **ASTs** unit by unit (module body, class bodies, functions).
   Comment/whitespace-only edits → no tests. `x is None` ↔ `x == None` and the
   same for Enum members → equivalent.
3. Map each real change to tests:
   - statement inside a function/lambda → tests that executed that statement;
   - default-argument change → tests that called the function *and* ran a call
     that leaves that parameter out (every reference must be a direct call;
     dunder and decorated functions are not narrowed);
   - code that also runs while a module imports → plus every test that
     (transitively) imports that module (an exception there breaks them all);
   - class/module constant → tests that use the class/module, narrowed to tests
     executing a *use* of the value (followed through exact pass-throughs) when
     every reference is traceable, or to tests that built the expression type
     for dicts keyed by expression classes (`TRANSFORMS`, type metadata).
     When only dict *values* change, `k in D`, `len(D)` and truth tests of D are
     not uses. A constant read through the class name (`Foo.X`) is not narrowed
     to users of the class;
   - a literal class attribute removed or added → same use tracing, where for a
     removal every reference (pass-throughs included) can raise;
   - docstring edits (still non-empty) → nothing: `__doc__` is only tested for
     emptiness and doctests are not in the collected suite;
   - class constant of a class some module instantiates while importing →
     plus every test that imports that module (the import can now raise);
   - non-literal import-time edits → all importers;
   - data files → tests that read them; new/removed files → directory readers.
4. Anything unparseable/unknown falls back to a broad, safe set.
5. Schedule: LPT for k = 1..8 workers plus a move/swap local search; pick the
   minimum of `max load + 2 s × k`.

## Rules we respect

- Index and packaged source derive only from the pinned commit; `sample/answers.json`
  is read only by `score.py` / `tools/evaluate.py`, never by the image.
- stdout carries only JSON lines; diagnostics go to stderr (`RWX_DEBUG=1`).
- Runtime: no network, read-only filesystem, no writes.
- `index/source.json.gz` packages sqlglot's MIT-licensed source (`index/SQLGLOT_LICENSE`).

## Commands

```powershell
$env:RWX_DATA = (Resolve-Path .\sample).Path
cmd /c "python selector.py > output.jsonl"      # avoids PowerShell 5.1 UTF-16 redirection
python score.py sample sample/answers.json output.jsonl
python -m unittest discover -s tests_local -v
```

```bash
make sample        # organizer Docker flags, then score
make check
tools/trace_suite.sh /tmp/indexbuild               # rebuild index/ from the pinned commit
python tools/evaluate.py sample sample/answers.json output.jsonl   # per-commit costs
```

## Files

- `selector.py` — judge entry point.
- `index/` — pinned-commit-derived coverage/trace index + pinned source (≈1.8 MB),
  and `trace_cache.json.gz`: use traces and call sites of every constant/function
  name of the pinned source, precomputed by `tools/build_trace_cache.py`. It holds
  a hash of the tracing code; the selector ignores it (and traces live) if that
  code changes. `tests_local` checks it is fresh.
- `tools/` — offline index build, tracing plugin, mutation generator, ground-truth
  runner, evaluators. Not copied into the image.
- `benchmarks/holdout/` — independent holdout patches and their measured labels.
- `docs/research/` — research pack (design, experiments, risks).
- `score.py`, `SCORING.md`, `Makefile`, `sample/` — organizer files, unmodified.
